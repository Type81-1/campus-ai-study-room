## 1. 引言

### 1.1 目的

本文档定义校园 AI 智能自习室预约系统的功能需求、业务规则、非功能需求与外部接口，作为设计、实现、测试和验收的共同依据。读者对象为课程指导教师、项目组成员与验收评审。

### 1.2 范围

**系统内**：

- 学生端：登录、座位查询、预约、取消、签到、结束自习、智能推荐、我的预约；
- 管理端：运营统计看板、违规占座预警与处理、座位维护、用户概览；
- 系统级：时段冲突拦截、违规自动判定与扫描、实时状态推送、权限控制。

**系统外（本期不做）**：

- 与学校统一身份认证（CAS/OAuth）对接、短信/微信通知；
- 真实闸机、门禁、人脸识别等硬件联动；
- 多机房分布式部署与多进程事件广播（当前为单进程 SSE）；
- 移动端原生 App / 小程序。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| 时段（Slot） | 某日期上的一段连续时间，最小粒度 30 分钟，单次最长 4 小时 |
| 冲突 | 同一座位、同一日期、两个时段区间有交集且状态有效 |
| 签到窗口 | 允许签到的时间范围：`[开始 − 30 分钟, 开始 + 15 分钟]` |
| 超时未签到（no_show） | 超过签到窗口上界仍未签到 |
| 超时占用（overstay） | 签到后超过结束时间 30 分钟仍未结束 |
| 座位热度 | 目标时段已占用座位数 ÷ 总座位数 |
| 令牌（Token） | 登录后签发的随机串，服务端只保存其 SHA-256 摘要 |

## 2. 总体描述

### 2.1 产品定位

面向高校自习室的 B/S 预约系统。要解决的四个原始问题：

| 原始问题 | 对应设计 |
| --- | --- |
| 传统预约系统固定排班 | 学生自主选日期、时段、座位，按需预约 |
| 座位资源浪费 | 超时未签到自动释放座位；违规累计限制预约 |
| 占座乱象 | 违规占座预警（no_show / overstay）+ 管理员处置闭环 |
| 多人并发预约、隐私保护 | 写事务内行锁防超订；令牌鉴权 + 不暴露他人预约 |

### 2.2 用户角色

| 角色 | 说明 | 权限范围 |
| --- | --- | --- |
| 学生（student） | 在校学生 | 查询座位、预约/取消自己的预约、签到/结束、查看推荐、查看自己的预约 |
| 管理员（admin） | 自习室管理人员 | 学生的全部权限 + 统计看板、违规处理、座位维护、用户概览；可取消任意预约 |
| 定时任务（sweeper） | 系统内部角色 | 周期性扫描超时预约并生成违规 |

### 2.3 运行环境

| 项 | 要求 |
| --- | --- |
| 服务端 | Python 3.10+（标准库 `http.server`）；MySQL 模式需 `PyMySQL` |
| 数据库 | MySQL 8.0（InnoDB / utf8mb4）；或 SQLite 3（本地演示与测试） |
| 客户端 | 支持 ES Module 的现代浏览器（Chrome 61+ / Edge 79+ / Firefox 60+ / Safari 11+） |
| 网络 | 单机或局域网；SSE 需要浏览器支持 `EventSource` |

### 2.4 设计与实现约束

1. **分层架构**：传输层 → 接口层 → 服务层 → 仓储层 → 数据底座，单向依赖；
2. **数据库**：正式环境使用 MySQL；SQLite 仅用于本地演示与自动化测试；
3. **并发**：创建预约必须在同一事务内完成「锁座位行 → 查冲突 → 插入」；
4. **身份**：接口不得接受客户端传入的用户标识，身份只能由令牌解析；
5. **可测试**：业务规则（时段、签到窗口、违规判定、推荐打分）须实现为纯函数。

## 3. 功能需求

优先级：**P0** 必须（验收硬指标）、**P1** 重要、**P2** 增强。

### 3.1 用户模块

| 编号 | 需求 | 说明 | 验收标准 | 优先级 |
| --- | --- | --- | --- | --- |
| FR-01 | 登录 | 账号 + 口令登录，成功后返回令牌、过期时间与用户信息 | 正确凭证返回 200 与令牌；错误凭证 401；响应不含口令字段 | P0 |
| FR-02 | 口令安全存储 | 口令以 PBKDF2-HMAC-SHA256（20 万次迭代 + 每用户独立盐）存储 | 数据库中口令字段以 `pbkdf2_sha256$` 开头；同口令不同用户哈希不同 | P0 |
| FR-03 | 会话管理 | 令牌有效期 7 天（可配置）；支持主动登出 | 登出后同一令牌访问返回 401；过期令牌返回 401 | P0 |
| FR-04 | 当前用户 | 提供 `/api/me` 供前端恢复会话 | 携带有效令牌返回当前用户；无令牌 401 | P1 |
| FR-05 | 用户概览 | 管理员查看用户列表，含预约数与待处理违规数 | 列表不含口令字段；计数与库内数据一致 | P1 |

### 3.2 预约模块

| 编号 | 需求 | 说明 | 验收标准 | 优先级 |
| --- | --- | --- | --- | --- |
| FR-06 | 座位查询 | 按日期与时段返回全部座位及可用状态 | 返回 24 个座位；可用性按该时段冲突实时计算；维护中座位标记为「维护中」 | P0 |
| FR-07 | 创建预约 | 学生选择座位与时段创建预约 | 成功 201；同座位时段冲突 409；同用户同时段重复 409；非法时段 400；座位/用户不存在 404 | P0 |
| FR-08 | 取消预约 | 本人或管理员可取消 `booked` 状态的预约 | 成功 200 且座位立即释放；越权 403；已签到/已完成 409 | P0 |
| FR-09 | 签到核销 | 在签到窗口内将预约置为 `checked_in` | 窗口内 200；过早 409 并提示可签到时段；超时 409 且预约置 `expired` 并记违规 | P0 |
| FR-10 | 结束自习 | `booked` / `checked_in` 可置为 `completed` | 成功 200；重复结束 409；非本人 403 | P0 |
| FR-11 | 我的预约 | 只返回当前登录用户的预约 | 不因请求参数变化返回他人数据；列表含可签到时段提示 | P0 |

### 3.3 智能推荐模块

| 编号 | 需求 | 说明 | 验收标准 | 优先级 |
| --- | --- | --- | --- | --- |
| FR-12 | 空闲座位推荐 | 按可解释规则打分排序，返回前 5 个空闲座位 | 结果按分数降序；每项附带理由文案；已占用与维护中座位被排除 | P1 |
| FR-13 | 时段热度提示 | 返回目标时段的占用率、紧张程度与建议 | 占用率 = 已占用 ÷ 总数；分档为「空闲/较松/较紧张/接近满座」并给出建议语 | P2 |

推荐评分规则见 4.6。

### 3.4 后台管理模块

| 编号 | 需求 | 说明 | 验收标准 | 优先级 |
| --- | --- | --- | --- | --- |
| FR-14 | 违规预警列表 | 管理员查看违规记录（类型、说明、时间、状态） | 列表按时间倒序；含座位号与时段；未处理的显示「待处理」 | P0 |
| FR-15 | 违规处理 | 管理员将违规置为已处理 | 成功 200；重复处理 404；学生调用 403 | P0 |
| FR-16 | 违规自动扫描 | 后台线程每 60 秒扫描一次，也支持手动触发 | 扫描幂等：同一预约同类违规只记一次；返回失效/超时/新增违规数量 | P0 |
| FR-17 | 座位维护 | 管理员切换座位状态 `available` / `maintenance` | 维护中的座位不可被预约（409）；可恢复；非法状态值 400 | P1 |
| FR-18 | 状态实时推送 | 预约/取消/签到/座位维护后向已连接客户端推送事件 | 客户端 1 秒内收到对应类型事件；无令牌连接被拒绝（401） | P2 |

| --- | --- | --- | --- | --- |

## 4. 业务规则

| 编号 | 规则 | 参数（可配置） |
| --- | --- | --- |
| BR-01 | 只能预约当天及以后，不能预约过去日期 | — |
| BR-02 | 时段按整点/半点填写，结束必须晚于开始 | `ALLOWED_MINUTES = {0, 30}` |
| BR-03 | 单次预约最长 4 小时 | `MAX_DURATION = 4h` |
| BR-04 | 同一座位同一日期时段不得重叠（半开区间 `[start, end)`） | — |
| BR-05 | 同一用户在重叠时段只能有一个有效预约 | — |
| BR-06 | 签到窗口 = [开始 − 30 分钟, 开始 + 15 分钟] | `CHECKIN_EARLY_MINUTES=30`、`NO_SHOW_GRACE_MINUTES=15` |
| BR-07 | 预约开始后超过 15 分钟未签到 → 预约 `expired` + `no_show` 违规 | `NO_SHOW_GRACE_MINUTES` |
| BR-08 | 签到后超过结束时间 30 分钟未结束 → 预约 `completed` + `overstay` 违规 | `OVERSTAY_GRACE_MINUTES=30` |
| BR-09 | 近 30 天未处理违规 ≥ 3 条 → 禁止预约，处理后可恢复 | `VIOLATION_WINDOW_DAYS=30`、`VIOLATION_BLOCK_THRESHOLD=3` |
| BR-10 | 维护中的座位不可预约 | `seats.status` |
| BR-11 | 每个请求的身份只能来自令牌，不接受客户端传入的 user_id | `Authorization: Bearer` |
| BR-12 | 令牌有效期 7 天，从登录时刻起算（不随请求刷新） | `SESSION_TTL_DAYS=7` |

### 4.6 推荐评分规则

| 因子 | 分值 | 触发条件 |
| --- | --- | --- |
| 基础分 | 50 | 所有空闲座位 |
| 靠窗偏好 | +25 | 用户偏好 `window=true` 且座位靠窗 |
| 电源偏好 | +20 | 用户偏好 `power=true` 且座位有电源 |
| 安静区 | +5 | 座位区域为「安静区」 |
| 冷门座位 | +5 | 该座位近 7 天预约次数 ≤ 人均，且人均 ≥ 1（历史不足时不做冷热区分） |
| 前后时段空闲 | +5 | 目标时段前后各 1 小时该座位也空闲 |

同分按座位 ID 升序，保证结果可复现。时段热度只做提示，不参与打分。

### 6.2 数据保留

- 本地 SQLite 库文件不上传仓库（`.gitignore` 已忽略 `*.db`）。

## 7. 外部接口需求

### 7.1 接口风格

REST + JSON，统一返回结构：

```json
{ "ok": true,  "...": "业务字段" }
{ "ok": false, "code": "conflict", "message": "该座位在所选时段已被预约，请选择其他座位" }
```

鉴权：除 `/api/health`、`/api/login` 外均需 `Authorization: Bearer <token>`。

### 7.2 接口清单

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/health` | 公开 | 健康检查 |
| POST | `/api/login` | 公开 | 登录，返回令牌 |
| POST | `/api/logout` | 登录 | 退出登录 |
| GET | `/api/me` | 登录 | 当前用户 |
| GET | `/api/seats` | 登录 | 座位状态 |
| GET | `/api/reservations` | 登录 | 我的预约 |
| POST | `/api/reservations` | 登录 | 创建预约 |
| DELETE | `/api/reservations/{id}` | 本人/管理员 | 取消预约 |
| POST | `/api/reservations/{id}/checkin` | 本人/管理员 | 签到 |
| POST | `/api/reservations/{id}/checkout` | 本人/管理员 | 结束自习 |
| GET | `/api/recommendations` | 登录 | 推荐 + 热度上下文 |
| GET | `/api/events?token=` | 登录 | SSE 实时事件流 |

### 7.3 SSE 事件

`GET /api/events` 返回 `text/event-stream`，事件类型：

| 事件 | 触发时机 | 载荷 |
| --- | --- | --- |
| `reservation.created` | 创建预约成功 | `seat_id`、`date`、`start`、`end` |
| `reservation.cancelled` | 取消预约 | `reservation_id` |
| `reservation.checked_in` / `checked_out` | 签到 / 结束 | `reservation_id` |
| `seat.status` | 座位维护状态变化 | `seat_id`、`status` |
| `violation.scanned` / `violation.resolved` | 扫描完成 / 处理违规 | `summary` / `violation_id` |

心跳注释帧每 15 秒一次（`: ping`），断线后浏览器按 `retry: 3000` 自动重连。

### 7.4 错误码约定

| 状态码 | 含义 | 典型场景 |
| --- | --- | --- |
| 400 | 参数错误 | 缺字段、时段格式错误、非法座位状态 |
| 401 | 未认证 | 无令牌、令牌过期、口令错误 |
| 403 | 无权限 | 学生访问管理接口、操作他人预约 |
| 404 | 资源不存在 | 座位/预约/违规不存在 |
| 409 | 状态冲突 | 座位已被预约、重复签到、违规阈值限制 |
| 413 | 请求体过大 | 超过 1 MB |
| 500 | 服务端异常 | 未预期错误（日志记录堆栈） |

## 8. 用例描述

### UC-01 预约座位

| 项 | 内容 |
| --- | --- |
| 参与者 | 学生 |
| 前置条件 | 已登录，无达到阈值的未处理违规 |
| 主流程 | 1. 选择日期与时段 → 2. 查询座位 → 3. 选择空闲座位 → 4. 提交预约 → 5. 系统锁座位行、校验冲突、写入预约 → 6. 返回预约详情并推送事件 |
| 异常流 | 3a. 座位已被占用 → 409 提示换座；4a. 该时段已有本人预约 → 409；4b. 违规达到阈值 → 409 提示联系管理员；4c. 时段非法 → 400 |
| 后置条件 | 生成 `booked` 预约；该座位在此时段对其他用户显示「已占用」 |

### UC-02 签到核销

| 项 | 内容 |
| --- | --- |
| 参与者 | 学生（或管理员代办） |
| 前置条件 | 预约状态为 `booked` |
| 主流程 | 1. 打开我的预约 → 2. 在签到窗口内点击签到 → 3. 状态置 `checked_in` 并记录签到时间 |
| 异常流 | 1a. 早于窗口 → 409 提示「可签到时段 hh:mm-hh:mm」；2a. 晚于窗口 → 预约置 `expired` 并生成 `no_show` 违规；2b. 非本人 → 403；2c. 已签到 → 409 |
| 后置条件 | 状态流转正确；超时场景下座位被释放 |

### UC-03 违规处置

| 项 | 内容 |
| --- | --- |
| 参与者 | 管理员、定时任务 |
| 前置条件 | 存在超时未签到或超时未结束的预约 |
| 主流程 | 1. 定时任务每 60 秒扫描 → 2. 命中规则的预约流转状态并生成违规 → 3. 管理员查看看板 → 4. 点击「标记已处理」 |
| 异常流 | 1a. 扫描重复执行 → 幂等（唯一键兜底）；3a. 学生调用处理接口 → 403 |
| 后置条件 | 违规记录状态为 `resolved`；该用户违规计数下降，达到阈值以下即可恢复预约 |
