## 2. 模块划分（对应任务书「五大模块」）

| 任务书模块 | 代码位置 | 职责 |
| --- | --- | --- |
| 用户模块 | `services/auth_service.py`、`repositories/user_repository.py` | 登录、身份校验、角色判定、用户列表 |
| 预约模块 | `services/reservation_service.py`、`services/slot_rules.py`、`repositories/{seat,reservation}_repository.py` | 座位查询、时段校验、创建/取消预约、签到核销、结束自习 |
| 智能推荐模块 | `services/recommendation_service.py` | 空闲座位筛选与可解释打分排序 |
| 后台管理模块 | `services/violation_service.py`、`backend/sweeper.py`、`api/router.py`（admin 路由） | 违规占座判定与预警、定时扫描、违规处理、权限校验 |
| 数据统计模块 | `services/stats_service.py`、`repositories/stats_repository.py` | 预约总量、今日、在学人数、取消率、违规率、热门座位、趋势、时段与楼层分布 |

## 5. 时序图：创建预约（并发安全）

```mermaid
sequenceDiagram
    actor Student as 学生
    participant FE as 前端 app.js
    participant API as Api
    participant SVC as ReservationService
    participant DB as Session / MySQL·SQLite

    Student->>FE: 选日期、时段、座位
    FE->>API: POST /api/reservations
    API->>API: 校验必填字段
    API->>SVC: create(user_id, seat_id, day, start, end)
    SVC->>SVC: parse_slot() 校验时段规则
    SVC->>DB: BEGIN（SQLite: IMMEDIATE）
    SVC->>DB: 校验用户 + 违规阈值
    SVC->>DB: lock_row(seats, seat_id)  ← MySQL: FOR UPDATE
    SVC->>DB: find_overlap(seat_id, day, start, end)
    alt 时段已被占用
        DB-->>SVC: 命中冲突
        SVC->>DB: ROLLBACK
        SVC-->>API: ConflictError 409
        API-->>FE: 409 该座位已被预约
    else 可以预约
        SVC->>DB: INSERT reservations
        SVC->>DB: COMMIT
        SVC-->>API: 预约详情
        API-->>FE: 201 预约成功
    end
```

关键是「锁 → 查 → 写」在同一事务内完成，杜绝两个请求同时通过冲突检查。

## 6. 时序图：违规扫描与预警

```mermaid
sequenceDiagram
    participant SW as ViolationSweeper
    participant SVC as ViolationService
    participant DB as Session
    participant Admin as 管理员

    loop 每 SWEEPER_INTERVAL 秒（默认 60s）
        SW->>SVC: scan(now)
        SVC->>DB: list_sweepable(今天及之前, booked/checked_in)
        DB-->>SVC: 待扫描预约列表
        loop 每条预约
            SVC->>SVC: decide() 纯规则判定
            alt 超时未签到
                SVC->>DB: status = expired
                SVC->>DB: INSERT violations(no_show)
            else 超时未结束
                SVC->>DB: status = completed
                SVC->>DB: INSERT violations(overstay)
            end
        end
        SVC-->>SW: {expired, overstay, violations}
    end

    Admin->>SVC: POST /api/admin/violations/scan（手动触发）
    Admin->>SVC: GET /api/admin/violations
    SVC-->>Admin: 违规列表（含座位、时段、文案）
    Admin->>SVC: POST /api/admin/violations/{id}/resolve
    SVC->>DB: status = resolved
```

## 7. 数据库 E-R 图

```mermaid
erDiagram
    USERS {
        INT id PK
        VARCHAR username UK
        VARCHAR password
        VARCHAR name
        VARCHAR role
        VARCHAR preferences
        DATETIME created_at
    }
    SEATS {
        INT id PK
        VARCHAR code UK
        TINYINT floor
        VARCHAR zone
        VARCHAR seat_type
        TINYINT near_window
        TINYINT power
        VARCHAR status
    }
    RESERVATIONS {
        INT id PK
        INT user_id FK
        INT seat_id FK
        DATE reservation_date
        TIME start_time
        TIME end_time
        VARCHAR status
        DATETIME created_at
        DATETIME checkin_at
    }
    VIOLATIONS {
        INT id PK
        INT user_id FK
        INT reservation_id FK
        VARCHAR kind
        VARCHAR message
        VARCHAR status
        DATETIME created_at
    }
    USERS ||--o{ RESERVATIONS : creates
    SEATS ||--o{ RESERVATIONS : receives
    USERS ||--o{ VIOLATIONS : has
    RESERVATIONS ||--o{ VIOLATIONS : may_trigger
```

关键约束：

| 约束 | 作用 |
| --- | --- |
| `uk_reservation_user_slot(user_id, reservation_date, start_time, end_time)` | 同一用户同一时段不可重复预约（数据库兜底） |
| `uk_violation_reservation_kind(reservation_id, kind)` | 同一预约同类违规只记一次（扫描幂等） |
| `idx_reservation_slot(seat_id, reservation_date, start_time, end_time)` | 冲突检查走索引 |
| `idx_reservation_status(status, reservation_date)` | 扫描任务按状态过滤 |
| `idx_violation_user(user_id, status, created_at)` | 违规阈值统计 |

> SQLite 版本见 `database/sqlite/schema.sql`，字段语义一致，仅类型与自增写法不同。

## 8. 预约状态流转

```mermaid
stateDiagram-v2
    [*] --> booked: 创建预约
    booked --> checked_in: 签到核销
    checked_in --> completed: 结束自习
    booked --> cancelled: 用户取消
    booked --> expired: 超时未签到（扫描任务）
    checked_in --> completed: 超时未结束（扫描任务，记 overstay）
    cancelled --> [*]
    expired --> [*]
    completed --> [*]
```

v1 中 `expired` 只存在于图里、代码从不产生；v2 起由违规扫描真实触发。
