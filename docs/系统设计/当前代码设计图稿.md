## 5. 时序图：登录与令牌鉴权（v2.1）

```mermaid
sequenceDiagram
    actor User as 用户
    participant FE as 前端 main.js
    participant API as Api
    participant AUTH as auth_service
    participant DB as Session

    User->>FE: 输入账号密码
    FE->>API: POST /api/login
    API->>AUTH: login(username, password)
    AUTH->>DB: 按用户名取用户（含口令哈希）
    AUTH->>AUTH: verify_password()：PBKDF2 比对
    alt 校验失败
        AUTH-->>API: AuthError 401
        API-->>FE: 401 账号或密码错误
    else 校验通过
        AUTH->>DB: INSERT sessions(token_hash, expires_at)
        AUTH-->>API: {token, expires_at, user}
        API-->>FE: 200 令牌
        FE->>FE: 令牌写入 localStorage
    end

    Note over FE,DB: 后续每个请求
    FE->>API: GET /api/...（Authorization: Bearer token）
    API->>AUTH: authenticate(token)
    AUTH->>DB: 按 token 的 SHA-256 摘要查会话（只读事务）
    DB-->>AUTH: 用户信息 + 过期时间
    AUTH-->>API: actor
    API->>API: require_admin(actor) / ensure_owner_or_admin()
```

设计要点：

1. **令牌只存摘要**：库里是 `sha256(token)`，即使数据库泄露也无法直接复用令牌；
2. **鉴权走只读事务**：每个请求都会鉴权，若在此处做任何写操作都会抢写锁（SQLite 为库级串行锁），因此令牌采用「登录时刻起算的绝对有效期」，不在请求路径上刷新活跃时间；
3. **身份不来自前端**：`user_id` 参数已从所有接口移除，越权只能靠「拿到别人的令牌」，而不是改一个数字。

## 6. 时序图：创建预约（并发安全）

```mermaid
sequenceDiagram
    actor Student as 学生
    participant FE as 前端 booking.js
    participant API as Api
    participant SVC as ReservationService
    participant DB as Session / MySQL·SQLite

    Student->>FE: 选日期、时段、座位
    FE->>API: POST /api/reservations（Bearer 令牌）
    API->>API: authenticate / 校验必填字段
    API->>SVC: create(actor, seat_id, day, start, end)
    SVC->>SVC: parse_slot() 校验时段规则
    SVC->>DB: BEGIN（SQLite: IMMEDIATE）
    SVC->>DB: 校验违规阈值
    SVC->>DB: lock_row(seats, seat_id)  ← MySQL: FOR UPDATE
    SVC->>DB: find_overlap(seat_id, day, start, end)
    alt 时段已被占用
        DB-->>SVC: 命中冲突
        SVC->>DB: ROLLBACK
        SVC-->>API: ConflictError 409
        API-->>FE: 409 该座位已被预约
    else 可以预约
        SVC->>DB: INSERT reservations
        SVC->>DB: COMMIT
        SVC-->>API: 预约详情
        API-->>FE: 201 预约成功
    end
```

关键是「锁 → 查 → 写」在同一事务内完成，杜绝两个请求同时通过冲突检查。

## 7. 时序图：违规扫描与预警

```mermaid
sequenceDiagram
    participant SW as ViolationSweeper
    participant SVC as ViolationService
    participant DB as Session
    participant Admin as 管理员

    loop 每 SWEEPER_INTERVAL 秒（默认 60s）
        SW->>SVC: scan(now)
        SVC->>DB: list_sweepable(今天及之前, booked/checked_in)
        DB-->>SVC: 待扫描预约列表
        loop 每条预约
            SVC->>SVC: decide() 纯规则判定
            alt 超时未签到
                SVC->>DB: status = expired
                SVC->>DB: INSERT violations(no_show)
            else 超时未结束
                SVC->>DB: status = completed
                SVC->>DB: INSERT violations(overstay)
            end
        end
        SVC-->>SW: {expired, overstay, violations}
    end

    Admin->>SVC: POST /api/admin/violations/scan（手动触发）
    Admin->>SVC: GET /api/admin/violations
    SVC-->>Admin: 违规列表（含座位、时段、文案）
    Admin->>SVC: POST /api/admin/violations/{id}/resolve
    SVC->>DB: status = resolved
```

「超时签到」与扫描共用同一套规则：`ReservationService.checkin` 判定为 `late` 时调用 `ViolationService.apply()`，保证线上判定与定时任务口径一致。

## 8. 时序图：SSE 实时推送（v2.2）

```mermaid
sequenceDiagram
    participant FE as 前端 realtime.js
    participant WEB as StudyRoomHandler
    participant API as Api
    participant BUS as EventBus
    participant SVC as ReservationService

    FE->>WEB: GET /api/events?token=...
    WEB->>API: authenticate(token)
    alt 令牌无效
        API-->>WEB: AuthError
        WEB-->>FE: 401 JSON
    else 令牌有效
        WEB->>BUS: subscribe()
        WEB-->>FE: 200 text/event-stream (chunked)
        WEB-->>FE: : connected as 用户名

        Note over SVC,BUS: 任一用户下单/取消/签到或管理员维护座位
        SVC-->>API: 业务完成
        API->>BUS: publish("reservation.created", {...})
        BUS-->>WEB: 事件入队
        WEB-->>FE: event: reservation.created / data: {...}

        loop 每 SSE_HEARTBEAT_SECONDS 秒无事件
            WEB-->>FE: : ping
        end

        FE->>FE: 500ms 去抖后刷新座位/看板
    end
```

要点：

1. **发布不阻塞**：订阅队列满时丢弃最旧事件，慢客户端不会拖住请求线程；
2. **连接有上限**：超过 `SSE_MAX_CLIENTS`（默认 50）返回 503，防止线程被占满；
3. **鉴权方式**：`EventSource` 无法自定义请求头，因此允许 `?token=` 传令牌；令牌仍是短期会话令牌；
4. **单进程**：事件总线是进程内实现，多进程部署需换 Redis Pub/Sub，`EventBus` 接口保持不变。

## 10. 预约状态流转

```mermaid
stateDiagram-v2
    [*] --> booked: 创建预约
    booked --> checked_in: 签到核销（开始前 30 分钟至开始后 15 分钟内）
    checked_in --> completed: 结束自习
    booked --> cancelled: 用户取消
    booked --> expired: 超时未签到（定时扫描 / 超时签到）
    checked_in --> completed: 超时未结束（扫描任务，记 overstay）
    cancelled --> [*]
    expired --> [*]
    completed --> [*]
```

签到窗口：`[开始 - CHECKIN_EARLY_MINUTES, 开始 + NO_SHOW_GRACE_MINUTES]`，区间外分别返回「还未到签到时间」与「已超过签到截止时间（预约失效并记违规）」。
