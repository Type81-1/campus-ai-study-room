## 4. 创建预约时序图

```mermaid
sequenceDiagram
    actor Student as 学生
    participant Frontend as 前端 app.js
    participant API as StudyRoomHandler
    participant DB as SQLite
    Student->>Frontend: 选择日期、时段和座位
    Frontend->>API: POST /api/reservations
    API->>API: 校验必填字段和时间范围
    API->>DB: 查询座位是否存在
    API->>DB: conflict() 检查重叠预约
    alt 座位时段冲突
        DB-->>API: 返回已有预约
        API-->>Frontend: 409 冲突
        Frontend-->>Student: 提示已被预约
    else 可以预约
        API->>DB: INSERT reservations
        DB-->>API: 返回预约记录
        API-->>Frontend: 201 预约成功
        Frontend-->>Student: 显示成功提示并刷新座位
    end
```

## 5. 签到与结束自习时序图

```mermaid
sequenceDiagram
    actor Student as 学生
    participant Frontend as 前端 app.js
    participant API as StudyRoomHandler
    participant DB as SQLite
    Student->>Frontend: 点击签到核销
    Frontend->>API: POST /api/reservations/{id}/checkin
    API->>DB: 查询预约、用户和权限
    alt 状态为 booked 且有权限
        API->>DB: 更新 status=checked_in
        API-->>Frontend: 签到成功
        Frontend-->>Student: 显示“签到成功”
        Student->>Frontend: 点击结束自习
        Frontend->>API: POST /api/reservations/{id}/checkout
        API->>DB: 更新 status=completed
        API-->>Frontend: 结束成功
    else 预约无效、重复签到或越权
        API-->>Frontend: 返回错误
        Frontend-->>Student: 显示错误提示
    end
```

## 8. 代码接口与图的对应关系

| 设计对象 | 当前代码对应位置 |
|---|---|
| 登录用例 | `POST /api/login`、`frontend/app.js` 的 `login()` |
| 座位查询 | `GET /api/seats`、`build_seats()`、`loadSeats()` |
| 创建预约 | `POST /api/reservations`、`create_reservation()` |
| 冲突拦截 | `conflict()` 和 `create_reservation()` |
| 签到核销 | `POST /api/reservations/{id}/checkin`、`checkin()` |
| 结束自习 | `POST /api/reservations/{id}/checkout`、`checkout()` |
| 推荐 | `GET /api/recommendations`、`recommendations()` |
| 管理统计 | `GET /api/admin/stats`、`admin_stats()` |
| 违规预警接口 | `GET /api/admin/violations`、`POST /api/admin/violations/{id}/resolve` |
| 数据模型 | `backend/server.py` 中的 `users`、`seats`、`reservations`、`violations` 建表语句 |

## 9. 当前版本需要在答辩中说明的边界

- 当前推荐使用规则评分，属于可解释的轻量化推荐，不是机器学习模型。
- 当前后端使用 SQLite，适合课程设计演示；若部署为多人生产系统，可以替换为 MySQL。
- 当前已实现预约冲突校验和多线程 HTTP 服务，正式报告中的并发压力测试还需要单独补充测试数据和测试结果。
- 违规记录表和管理员预警接口已经预留，但当前原型没有自动生成复杂的违规判定规则，后续可以补充“预约后未签到”等规则。
